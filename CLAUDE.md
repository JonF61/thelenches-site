## Tools and their limits
- Sheet, reading: use the **Read Sheet tab** workflow (`read-sheet-tab.yml`, `scripts/sheettab`), not the whole Sheet via Drive. Dispatch it with the GitHub MCP actions tools (inputs `tab`, optional `range` like A1:F20, `max_rows` default 50, at most 500), then read the job log: plain CSV whose first line names the columns and whose first field is the Sheet row number, so you can quote exact cells. It is read-only (spreadsheets.readonly), refuses the Subscribers, Do Not Send, Sends, Replies, Feedback, Deleted contacts, Sign-ups, Recommendations and Listing suggestions tabs, shows Contacts as names and roles only (profile, contributions and notes print as "(hidden)", `ignore` rows as "(ignored row)"; Jon agreed 25 Oct) and masks email addresses (logs may be public); never widen that (its logs are public). For those tabs, use /k (below), or ask Jon.
- Sheet, writing (31 Oct, Jon's choice): the **Write Sheet cells** workflow (`write-sheet.yml`, `scripts/sheetwrite`). Dispatch it with inputs `action` (set / append / undo), `tab`, `range` (set: top-left cell or block, e.g. N36), `values` (plain text for one cell or JSON rows like `["a","b"]`), `expect` (set over non-blank cells: their current values; without it the cells must be blank) and `undo_id`. Every write first adds a row to the **Kryten log** tab (id, at, action, tab, range, old, new, status, run; made by the run; Read Sheet tab shows it without old/new) and prints `Undo id: …`; `undo` restores the old values only if the cells still hold what was written. Whole-Sheet fallback: the nightly Lenches backup copy. ## Finishing a job
Follow the `finish-job` skill (`.claude/skills/finish-job/SKILL.md`: pre-push checks, commit, PR, merge, Build history, CLAUDE.md, devtasks.json, reply); the rules it carries out are below.

**PR description**: the record of the work. What changed (files and behaviour), anything Jon must do by hand (Sheet cells, settings, workflow pastes), how it was tested, and what to check on the next live/shadow run. Keep it factual and complete.

**Workflow files** (adding one, or a Sheet column: follow the `new-workflow-or-column` skill): commit `.github/workflows/` changes yourself in the PR, like any other file (Jon agreed 25 Oct; first done in PR 60), and dispatch manual workflows yourself with the GitHub MCP actions tools. **Plan doc**, once merged and without being asked: add an entry to the **Build history** tab in its style (a `### <title> (PR numbers, date)` heading and one dense bullet: what changed, files, columns, first live result) and make targeted edits to the Project Plan tab (status, design) if the plan changed. **Dev tasks**: at the end of every job, update `worker/src/admin/devtasks.json` (shown on the panel's Summary): add what is still outstanding, remove what is done. Never name private individuals there (the repo is public).
