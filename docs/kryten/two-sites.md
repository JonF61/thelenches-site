# Two sites: build stages and details

Moved word for word from CLAUDE.md on 28 Nov 2026 so it no longer loads every session. Read the bullet for a feature before changing it; keep each bullet dense and dated, as before.

- **Hosting** (stage 3, 16 Nov): the Lenches deploys from build.yml as before; Harvington from `build-harvington.yml` (pushes to sites/harvington, src, lib, .eleventy.js; nightly 00:07 UTC; manual), which builds with `SITE=harvington`, adds `CNAME` (site.json `domain`) and `.nojekyll`, and force-pushes the built pages as one commit to the build-only repo `JonF61/harvington-site` (Pages: main branch, root) using the deploy key secret `HARVINGTON_DEPLOY_KEY` (write access to that repo only; without it the run builds and stops). **Launched** (stage 7b, 16 Nov): the holding page is gone, Home (`sites/harvington/home.njk`) is at "/", `noindex` is off (robots.txt opens and names the sitemap, `sites/harvington/sitemap.njk`), and site.json has the four form URLs, `turnstileSiteKey` (the Lenches widget, hostname added by Jon), its own `cfAnalyticsToken`, `newsletterCounts`, `facebookGroup` and `teamUrl` (17 Nov: base.njk adds `?site=harvington` to the Team and Edit page links, so they open the panel and editor on Harvington; the editor sends that site on its calls and watches build-harvington.yml (runs.js `buildWorkflow`)). Its Home carries the Suggest an update form, as the Lenches Home does (base.njk leaves it off "/").
- **Sheets and workflows** (stage 4a, 16 Nov): each site.json has `sheetId` (the Lenches "Lenches Pipeline"; Harvington "Harvington Pipeline", made 16 Nov in its own Drive folder "Harvington Pipeline" beside the Lenches one, shared as Editor with both service accounts), read by `lib/site.js` `sheetId()` (a run's SHEET_ID env wins, for tests); no workflow hard-codes a Sheet id. Every workflow that touches the Sheet sets `SITE: ${{ github.event.client_payload.site || github.event.inputs.site || 'lenches' }}`, so a dispatch with `site` in its payload (or a Run workflow `site` input) runs for that site; schedules and workflow_run stay the Lenches, except ingest and publish (stage 4b). Shared concurrency groups and per-item ones end in the site. Read Sheet tab and Write Sheet cells have a `site` input. `sheet-setup.yml` (`scripts/sheetsetup`, manual, dry run unless apply is ticked) gives a new site's Sheet the Lenches tab names and header rows only (never data; never over a used row 1; Checker skipped) and a starter Settings tab: its own Submissions source, replies_mode shadow, newsletter_mode off, holiday_mode FALSE, auto_window blank, start_date today, the Lenches limits, addresses blank. Test: `scripts/test-sheetsetup.js` (also checks every workflow).
- **Pipeline for both sites** (stage 4b, 16 Nov): the Worker fires `ingest` once per site with a sheetId (payload `site`; the Lenches first), and each run reads its site.json `gmailLabel` (GMAIL_LABEL env only overrides; ingest.yml and diagnostic.yml no longer set it; the diagnostic checks every site's label). One email sent to both addresses carries both labels and belongs to the site listed first (the Lenches): the Harvington run logs it `skipped` "Also sent to the Lenches website: handled there". Holly writes as each site's assistant: replies.js `REPLY_FROM` = site.json `email`, `GUIDELINES_URL` from its `url`, the signature's role line from `hollySignoff`; every site's domain counts as our own (replies.js, subscriptions.js `ownDomain`); Holly's site facts (`scripts/ingest/sitefacts.js`, 18 Nov) use the run's site.json `url` and `email`, offer only the pages that site has (`pageExists`) and its own Living here sections, and read church services from its services.json or services.js (Harvington: the Lenches' ARCH rota); test `scripts/test-sitefacts-sites.js`; urgent.js subjects end "(Lenches)" / "(Harvington)" (lib/site.js `shortName`). extract.js's SITES rule: an item is for both sites unless it clearly matters to one community alone; then `sites` / `sites_reason`, written to the Pending column `sites` (added at the end the first time it is needed; blank = both; Jon can type `lenches` or `harvington` in it) and the note "Holly: only for the X website: …". Cross-site repeat: each run reads the other Sheet's Pending (waiting or live; google.js `readOtherTable`, read-only, never cached as this site's headers) and an item matching one there by title/date or image (`findRepeat`) gets "Possible repeat of <id> on the X website", possible_repeat TRUE and status pending. **Publish** (publish.yml, one run, both sites, group `publish`): each site's pipeline.json takes its own Pending's live items for it plus the other Sheet's live items for it (lib/site.js `itemSites`), its own copy winning a title/date clash; another site's image is copied from its `sites/<other>/images/items` or taken from the email (`imageForOther`), never writing to the other Sheet; it then dispatches build.yml and/or build-harvington.yml for whichever changed. Harvington started in shadow (replies_mode shadow, newsletter_mode off); both are now live in its Settings (checked 18 Nov), so its replies and newsletter go out on Jon's tap like the Lenches'; Holly's lessons, Contacts and Claude usage are per Sheet for now. Test: `scripts/test-twosites.js`.
- **Panel site switcher** (stage 4c-1, 16 Nov): the top bar shows each site's name and colour (sites.js `siteList`; the Lenches green, Harvington's palette green) as buttons; choosing one reopens the panel at `/admin?site=<site>` and remembers it (localStorage `panelSite`); each tab keeps the site in its address, so two tabs can show different sites. Every /admin/api call sends `x-site` (frames and new tabs: `?site=`; the page editor's calls too); handleAdmin refuses an unknown site (400, never taken as the Lenches) and uses `siteEnv(env, site)` (sites.js: SHEET_ID = that site's sheetId, the Lenches keeping wrangler.toml's; SITE; SITE_URL for another site), so every screen reads and writes the chosen site's Sheet (Submissions, Replies, Contacts, Outreach, Suggestions, Rimmer, Autonomy, Settings, Summary). core.js `dispatch` adds `client_payload.site` for any site but the Lenches (whose dispatches stay exactly as before, matching the email links), so decisions, Check email now, Rimmer's Check and Refresh go to that site's runs. State says which site it is for and the panel refuses a mismatch. The top bar's **Subscribers** chip (23 Nov, Jon) shows the shown site's live count: unique active Subscribers addresses not on Do Not Send (state `subscribers`, summary.js `subscriberCount`). **Shared or Lenches-only**: Holly lessons are one list in the Lenches Sheet for both sites (Jon, 16 Nov): the panel always reads and writes it there (`lenv`), and replies.js `primeLearning` reads it from the Lenches Sheet on another site's run; Photos is the Lenches' alone (hidden on Harvington's menu); Organisations/listings come from the Lenches' bundled data, so Harvington's is empty until its own data files exist (then bundle them per site in admin/index.js `orgsFor`). **4c-2** (16 Nov): Newsletter draft and stats show a "no newsletter yet" note while a non-Lenches site's Settings newsletter_mode is off (state `newsletterMode`; the top bar's Draft link hides too); Site visitors and Summary's Visitors count each site's own host (siteEnv `SITE_HOST` = site.json domain; visitors.js `hostFor`) and say "counted from launch" for a site without `cfAnalyticsToken` (sites.js `hasAnalytics`); the nightly visitor log and the veto-window cron (index.js `runVisitorLog`, `runAutoWindows`) run per site against its own Sheet, the Lenches first; Summary's Claude spend card adds every site's month and the total (summary `claudeSpendSites`, each Sheet's Claude usage tab); Messages leaves out every site's newsletter (messages.js `NEWSLETTER_SUBJECTS` from site.json `newsletterName`; Holly's sign-off is matched for both sites). Panel links to site pages use the site's `url`. Signed /a links made by another site's run carry `s` (scripts/ingest/links.js `signToken`), and /a sends the decision to that site. /k takes an optional `"site": "harvington"`. Tests: `worker/test/admin.test.mjs` (site switcher), `scripts/test-twosites.js`; browser check `worker/test/ui-sites.check.mjs`; `worker/test/autowindowcron.test.mjs`.

The Lenches' issue renders byte-for-byte as before. The Worker's Thursday slots (build 06:30, autosend 08:00, reminders 12:00 and 17:00) and Rimmer's Wednesday 19:00 newsletter check fire for the Lenches as before and for any other site whose Settings `newsletter_mode` is set and not off (index.js SLOTS `perSite`, `newsletterSites`).
